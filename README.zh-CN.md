# Awesome Proactive Agents

[English](README.md) | **中文**（英文版为唯一事实源，条目更新以英文版为准，中文版批量跟进）

> **常驻型 Agent 应该在什么时候出手？**
> 一张主动式 AI 辅助的领域地图：Agent 能看什么信号、如何决定行动、行动做什么、记住什么，以及我们怎么衡量这次介入值不值。

大多数 agent 研究问的是「agent 能不能完成任务」。这份清单围绕另一个问题组织：**「agent 现在该不该主动行动？」**这是常驻型助手（智能眼镜、MR 头显、环境侧 copilot）绕不开的时机问题。

**组织主轴**：介入是一个不确定性下的决策，
`介入 ⇔ E[行动收益] − E[打扰成本] > θ`
下面每一项工作，都按它推进了这个不等式的哪一部分归位。

*状态：v0.2 · 持续维护 · 欢迎 PR。*

## Taxonomy 总图

```
                 ┌─────────────────────────────────────────────┐
                 │            主动介入管线                      │
                 └─────────────────────────────────────────────┘

  1. 信号             2. 决策               3. 执行            4. 记忆
  看什么              何时出手              做什么             知道什么
  ───────             ───────              ───────            ───────
  视线 / 眼手          规则式                说话 / 显示        会话记忆
  场景变化             (偏离任务脚本)         GUI 操作           情景存储
  时间上下文           决策论式               物理引导           用户画像
  用户行为             (收益 − 成本)                            个人化阈值
        │                   │                    │                  │
        └───────────────────┴────────┬───────────┴──────────────────┘
                                     ▼
                 5. 评估与自我改进（闭环）
                 这次介入好不好？系统会不会变好？
                 离线：时机 precision/recall · 反感度 benchmark
                 在线：接受 / 关闭 / 「免打扰 3 天」= reward 事件
                 → 反馈回调 θ（最小的强化学习）
```

## 2 · 决策：何时出手

领域的核心层，也是历史最深的一层。两条现在的 MR 论文很少连起来的脉络：

### 决策论脉络（2000s–2010s：通知与注意力管理）

| 工作 | 出处 / 时间 | 贡献 |
|---|---|---|
| [Attention-Sensitive Alerting](https://arxiv.org/abs/1301.6707) | UAI 1999（Horvitz, Jacobs, Hovel） | 把提醒建模为期望效用：推迟的代价 vs 打扰的代价，在用户注意力不确定的条件下权衡；「等待」是有可计算价值的一等动作 |
| [Principles of Mixed-Initiative UI](https://doi.org/10.1145/302979.303030) | CHI 1999（Horvitz） | 决策几何：行动阈值*随用户专注深度上升*；把对话加为第三种动作后得到三路策略——沉默 / 先问 / 直接做——比现代助手把「澄清式提问」当 UX 模式重新发明早了 25 年 |
| [打断协调的四种基本方式](https://doi.org/10.1207/S15327051HCI1701_2) | HCI 2002（McFarlane） | 时机是一个*协调*问题：immediate / negotiated / mediated / scheduled 四种方式，36 人双任务实验对比。negotiated（系统宣告、用户挑时机）在多数设计目标上胜出——这个基线，现代主动式论文几乎从不跑 |
| [Learning and Reasoning about Interruption](https://www.microsoft.com/en-us/research/publication/learning-and-reasoning-about-interruption/) | ICMI 2003（Horvitz & Apacible） | 从桌面/日历/音频流中**用美元**（willingness-to-pay）学习打断成本，并能*预报*下一个低成本可打扰窗口；跨用户迁移的模型得分低于多数类猜测——反对人群级时机策略的长期警告 |
| [任务结构预测打断成本](https://doi.org/10.1145/1124772.1124882) | CHI 2006（Iqbal & Bailey） | 不用任何传感器、只从任务结构算打断成本：三个计划特征预测出恢复时延 3.7 倍的差距（464 → 1,702 ms）——这份价格恰好写在现代脚本跟随型 agent 自己手里的任务分解上 |
| [计算任务的中断与恢复](https://doi.org/10.1145/1240624.1240730) | CHI 2007（Iqbal & Horvitz） | 实地测得的量级：27 名信息工作者、2,267 小时日志——每次提醒约 20 分钟的中断弧线，27% 被挂起的窗口两小时后仍未恢复。把打断成本按响应时长计价的模型，差了两个数量级 |
| [InterruptMe](https://doi.org/10.1145/2632048.2632062) | UbiComp 2014（Pejović & Musolesi） | 打断成本是**路径依赖**的：前两小时里已有八条通知时，用户对下一条的情绪好感度腰斩——所以连发的情境驱动门控在「耗尽可打扰性」这个轴上*比随机还差* |
| [Beyond Interruptibility](https://dl.acm.org/doi/10.1145/3130956) | IMWUT 2017（Pielot 等） | 把问题从「能不能打扰」推进到「这是不是一个*适合触达的时机*」；337 人实地实验，引入行为历史后预测提升 5 倍 |
| [注意力管理系统综述](https://arxiv.org/abs/1806.06771) | IMWUT 2018（Anderson 等） | 这条脉络在 LLM 前夜的自画像：注意力碎片化、断点、延迟投递，成本项赖以生存的整套词汇 |
| [JITAI：即时自适应干预](https://doi.org/10.1007/s12160-016-9830-8) | Ann. Behav. Med. 2018（Nahum-Shani 等） | 移动健康领域的时机形式化：决策点、裁量变量、显式的「什么都不提供」动作、把负担与疲劳列为一等成本——但阈值是理论设定的自由参数，两侧期望都没有被估计 |
| [自适应通知调度的生产部署](https://doi.org/10.1145/3292500.3330732) | KDD 2019（Okoshi 等） | 基于断点的延迟投递：382,518 用户部署实验（点击率最高 +60.7%），随后全量上线 Yahoo! JAPAN **超 1000 万 Android 用户**，这条脉络的人群级实证 |
| [VR 里的时机预测](https://doi.org/10.1145/3491102.3517529) | CHI 2022（Chen 等） | 可打扰性预测早在主动式 MR 浪潮之前四年就进了头显，而这波浪潮没有引用它 |

### LLM 时代的主动式（2024–）

| 工作 | 出处 / 时间 | 决策机制 |
|---|---|---|
| [Proactive Agent](https://arxiv.org/abs/2410.12361) | arXiv 2024.10（清华） | 用人类接受/拒绝标注训练 reward model 模拟用户判断；ProactiveBench（6,790 事件），F1 66.47% |
| [YETI](https://arxiv.org/abs/2501.09355) | arXiv 2025.01 | 规则式：偏离已知任务脚本即介入（无成本项） |
| [Proactive Assistant Dialogue Generation](https://arxiv.org/abs/2506.05904) | arXiv 2025.06 | 从流式第一人称视频决定何时开口 |
| [VisionClaw](https://arxiv.org/abs/2604.03486) | arXiv 2026.04 | 无——感知常开、行动只由用户发起。2026 年最接近量产的系统用「不做时机决策」解决时机问题：人仍是那道门 |
| [PRISM](https://arxiv.org/abs/2602.01532) | arXiv 2026.02 | 当校准的 P(用户接受) 超过由**「漏帮 vs 误扰」不对称成本推导的阈值**才介入；ProactiveBench 上误报 −22.78%、F1 +20.14%。迄今最接近效用决策的重建 |
| [不用 LLM 决定何时唤醒](https://arxiv.org/abs/2605.30152) | arXiv 2026.05 | 时间图编码器输出逐事件触发概率，LLM 只在触发*之后*被调用（服务器快 4–7 倍，约 220 MiB）。决策层可能根本不是一个 LLM 问题 |
| [Pro²Assist](https://arxiv.org/abs/2605.04227) | arXiv 2026.05 | 长程程序性任务的步骤感知 AR 协助；把**时机准确率**当头牌指标（最高达基线 2.29 倍） |

**这份清单想暴露的 gap（2026-07 更新）**：1999–2017 那条脉络把*成本项*建模得很严谨，但没有能干活的执行者。LLM 时代有了强执行者，如今才开始重新发现成本项，而且是碎片式的：PRISM 定价误报，[Precision Proactivity](https://arxiv.org/abs/2505.10742) 度量认知负荷，[EgoSocial](https://arxiv.org/abs/2510.13105) 命名社交违和，门控类论文定价算力。没有人把这些碎片统一进一个 θ，也没有一篇继承 1999–2017 的形式化。另注意：三篇独立的 2026 工作（PRISM 的审慎门、时间图触发器、[前置感知器](https://arxiv.org/abs/2606.03236)）收敛于同一个**廉价门 / 昂贵执行者**架构，这个收敛本身领域还没有人点破。

## 5 · 评估与自我改进：闭环

标准化程度最低的一层，也是（按本清单的论点）卡住其他所有层的一层：没有可靠的 eval，介入质量的 RL reward 连定义都无从谈起。

### 在线反馈与自我改进

每个已部署的主动式系统本来就在产出一条 reward 流，而且大部分被丢弃了。显式用户动作（接受、关闭、「不再显示」、「免打扰 3 天」）就是 `(上下文, 介入)` 对上的带标注偏好数据。「免打扰 3 天」的信息量是双重的：既是对这次介入的强负反馈，*又是*用户直接写进策略里的硬约束。

反馈本身有纵深，信号越真实，归因越困难：

| 层级 | 信号 | 成本 | 归因 |
|---|---|---|---|
| **L0 显式** | 接受 / 关闭 / 免打扰 | 免费但稀疏且有偏 | 平凡 |
| **L1 隐式行为** | 用户是否照建议做了；视线停留还是躲避；被打断后的恢复时间；undo | 密集，用户零成本 | 易到中等 |
| **L2 结果** | 任务完成率变化、省下的时间、避免的错误 | 需要任务插桩 | 延迟 → credit assignment |
| **L3 长期** | 留存、信任、用户干脆关掉主动功能（终极负反馈） | 只能人群级 A/B | 最难 |

实践中观察到三个成熟度等级：

1. **只记日志**：反馈收集了，从未使用（今天多数产品）。
2. **阈值自适应**：按用户、按上下文更新 θ；一个参数，bandit 式。最小的强化学习，常驻型助手大概率该从这里起步。
3. **策略学习**：在介入上学一个 reward model（[Proactive Agent](https://arxiv.org/abs/2410.12361) 是它的离线版本）。

让这件事变难的不对称性：负信号又便宜又多（每次关闭都是一条），正信号又弱又延迟：没被打扰的用户什么都不说，明天省下十分钟的介入今天没有任何信号。这也是自我改进画在评估层内部、而不是独立第六层的原因：反馈边的质量上限就是定义它的度量的质量（`reward ⊆ eval`）。

### 缺失的度量（开放）

- **带成本项的时机 precision/recall**：PAUC（ProactiveVideoQA）是给时机动态打分的首个发表尝试，但一个只奖励抓住时机、不定价误扰的度量仍然只是半个度量。
- **反感度 / 打扰成本**：只看接受率可以被 hack（少触发或滥触发都能刷），需要成本侧度量。
- **延迟收益**：价值之后才兑现的介入，目前没有 credit assignment 的故事。

| YETI 2025 | SSIM + 脚本对齐 | 规则：偏离即介入，无成本项 | 有脚本的程序性 AR | HoloAssist |
| VisionClaw 2026 | 常开第一人称 | 无（用户发起；主动式=future work） | 开放世界眼镜 | 无 |
| SIAgent 2026 | 眼手 | 意图识别（是「听懂」，不是「何时出手」） | VR 任务 | 60+ 任务套件 |
| UI-TARS-2 2025 | GUI 状态 | 任务完成 reward（有 ground truth） | GUI/OS，封闭 | OSWorld 等 |
| PRISM 2026 | 事件流 | 校准 P(接受) 对不对称成本阈值 | 桌面任务 | ProactiveBench |

按列读这张表：信号越来越丰富，执行者越来越强，但**决策列仍然分裂成「没有成本项的规则」和「没有现代执行者的成本模型」两半**——PRISM 是第一座看得见的桥，但它只定价误报、只在桌面。eval 列在开放世界场景下仍没有共享的时机质量 benchmark（EgoSocial 最接近，但只测社交切片）。

## 开放问题（survey 的种子）

1. **没有 ground truth 的 reward。** GUI agent 有任务完成作 reward；介入质量没有等价物。什么样的 eval 能让 RL reward 变得可定义？
2. **成本项。** 到 2026 年，诚实的表述已不是「没人建模成本」，而是「成本被碎片式建模」：误报率（PRISM）、认知负荷（Precision Proactivity）、社交违和（EgoSocial）、算力（门控类）。没有人把碎片统一进一个 θ，也没有人继承 1999–2017 的效用形式化。
3. **无脚本的时机。** YETI 式偏离检测需要任务脚本，开放世界的日常场景没有脚本。
4. **延迟收益的 credit assignment。** 帮用户省下明天十分钟的介入，今天拿不到信号。
5. **个人化阈值。** 同一个 θ 对不同用户、上下文、时段都是错的，时机策略必须以记忆为条件。
6. **Benchmark 碎片化。** HoloAssist 的介入类型预测、ProactiveBench 的接受/拒绝、ProactiveEval 的对话框架、EgoSocial 的社交时机、PAUC 的时机动态各测一个切面；Pro²Bench 的五合一是第一步但仍锚定脚本。没有一个端到端覆盖开放世界 MR 的介入时机。
