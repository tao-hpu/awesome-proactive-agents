# Awesome Proactive Agents

[English](README.md) | **中文**（英文版为唯一事实源，条目更新以英文版为准，中文版批量跟进）

> **常驻型 Agent 应该在什么时候出手？**
> 一张主动式 AI 辅助的领域地图：Agent 能看什么信号、如何决定行动、行动做什么、记住什么，以及我们怎么衡量这次介入值不值。

大多数 agent 研究问的是「agent 能不能完成任务」。这份清单围绕另一个问题组织：**「agent 现在该不该主动行动？」**这是常驻型助手（智能眼镜、MR 头显、环境侧 copilot）绕不开的时机问题。

**组织主轴**：介入是一个不确定性下的决策，
`介入 ⇔ E[行动收益] − E[打扰成本] > θ`
下面每一项工作，都按它推进了这个不等式的哪一部分归位。

*状态：v0.1 骨架 · 持续维护 · 欢迎 PR。*

## Taxonomy 总图

```
                 ┌─────────────────────────────────────────────┐
                 │            主动介入管线                      │
                 └─────────────────────────────────────────────┘

  1. 信号             2. 决策               3. 执行            4. 记忆
  看什么              何时出手              做什么             知道什么
  ───────             ───────              ───────            ───────
  视线 / 眼手          规则式                说话 / 显示        会话记忆
  场景变化             (偏离任务脚本)         GUI 操作           情景存储
  时间上下文           决策论式               物理引导           用户画像
  用户行为             (收益 − 成本)                            个人化阈值
        │                   │                    │                  │
        └───────────────────┴────────┬───────────┴──────────────────┘
                                     ▼
                 5. 评估与自我改进（闭环）
                 这次介入好不好？系统会不会变好？
                 离线：时机 precision/recall · 反感度 benchmark
                 在线：接受 / 关闭 / 「免打扰 3 天」= reward 事件
                 → 反馈回调 θ（最小的强化学习）
```

## 2 · 决策：何时出手

领域的核心层，也是历史最深的一层。两条现在的 MR 论文很少连起来的脉络：

### 决策论脉络（2000s–2010s：通知与注意力管理）

| 工作 | 出处 / 时间 | 贡献 |
|---|---|---|
| [Attention-Sensitive Alerting](https://arxiv.org/abs/1301.6707) | UAI 1999（Horvitz, Jacobs, Hovel） | 把提醒建模为期望效用：推迟的代价 vs 打扰的代价，在用户注意力不确定的条件下权衡 |
| [Learning and Reasoning about Interruption](https://www.microsoft.com/en-us/research/publication/learning-and-reasoning-about-interruption/) | ICMI 2003（Horvitz & Apacible） | 从桌面活动流中学习可打扰性模型 |
| [Beyond Interruptibility](https://dl.acm.org/doi/10.1145/3130956) | IMWUT 2017（Pielot 等） | 把问题从「能不能打扰」推进到「这是不是一个*适合触达的时机*」；337 人实地实验，引入行为历史后预测提升 5 倍 |

### LLM 时代的主动式（2024–）

| 工作 | 出处 / 时间 | 决策机制 |
|---|---|---|
| [Proactive Agent](https://arxiv.org/abs/2410.12361) | arXiv 2024.10（清华） | 用人类接受/拒绝标注训练 reward model 模拟用户判断；ProactiveBench（6,790 事件），F1 66.47% |
| [YETI](https://arxiv.org/abs/2501.09355) | arXiv 2025.01 | 规则式：偏离已知任务脚本即介入（无成本项） |
| [Proactive Assistant Dialogue Generation](https://arxiv.org/abs/2506.05904) | arXiv 2025.06 | 从流式第一人称视频决定何时开口 |
| [VisionClaw](https://arxiv.org/abs/2604.03486) | arXiv 2026.04 | 常开眼镜上 agent 自主决策协助时机 |

**这份清单想暴露的 gap**：1999–2017 那条脉络把*成本项*建模得很严谨，但没有能干活的执行者；LLM 时代有了强执行者，却大多只检测「用户需要帮助」而不带成本项。几乎没有人在开放世界（无脚本）场景下，用现代模型重建完整的「收益 − 成本」决策。

## 3 · 执行：决定出手之后做什么

| 工作 | 出处 / 时间 | 能力 |
|---|---|---|
| [UI-TARS-2](https://arxiv.org/abs/2509.02544) | arXiv 2025.09（字节 Seed） | 多轮 RL GUI agent：数据飞轮 + 混合环境（GUI + 文件系统 + 终端）+ 统一沙箱；OSWorld 47.5、AndroidWorld 73.3。证明了*当 reward 有 ground truth（任务完成与否）时*多轮 RL 可行 |

|---|---|---|

## 5 · 评估与自我改进：闭环

标准化程度最低的一层，也是（按本清单的论点）卡住其他所有层的一层：没有可靠的 eval，介入质量的 RL reward 连定义都无从谈起。

### Benchmark 与数据集

| 资源 | 出处 / 时间 | 度量什么 |
|---|---|---|

### 在线反馈与自我改进

每个已部署的主动式系统本来就在产出一条 reward 流，而且大部分被丢弃了。显式用户动作（接受、关闭、「不再显示」、「免打扰 3 天」）就是 `(上下文, 介入)` 对上的带标注偏好数据。「免打扰 3 天」的信息量是双重的：既是对这次介入的强负反馈，*又是*用户直接写进策略里的硬约束。

反馈本身有纵深，信号越真实，归因越困难：

| 层级 | 信号 | 成本 | 归因 |
|---|---|---|---|
| **L0 显式** | 接受 / 关闭 / 免打扰 | 免费但稀疏且有偏 | 平凡 |
| **L1 隐式行为** | 用户是否照建议做了；视线停留还是躲避；被打断后的恢复时间；undo | 密集，用户零成本 | 易到中等 |
| **L2 结果** | 任务完成率变化、省下的时间、避免的错误 | 需要任务插桩 | 延迟 → credit assignment |
| **L3 长期** | 留存、信任、用户干脆关掉主动功能（终极负反馈） | 只能人群级 A/B | 最难 |

实践中观察到三个成熟度等级：

1. **只记日志**：反馈收集了，从未使用（今天多数产品）。
2. **阈值自适应**：按用户、按上下文更新 θ；一个参数，bandit 式。最小的强化学习，常驻型助手大概率该从这里起步。
3. **策略学习**：在介入上学一个 reward model（[Proactive Agent](https://arxiv.org/abs/2410.12361) 是它的离线版本）。

让这件事变难的不对称性：负信号又便宜又多（每次关闭都是一条），正信号又弱又延迟：没被打扰的用户什么都不说，明天省下十分钟的介入今天没有任何信号。这也是自我改进画在评估层内部、而不是独立第六层的原因：反馈边的质量上限就是定义它的度量的质量（`reward ⊆ eval`）。

### 缺失的度量（开放）

- **时机 precision/recall**：agent 选择介入的时刻里，多少是恰当的？恰当的时刻里，多少被抓住了？
- **反感度 / 打扰成本**：只看接受率可以被 hack（少触发或滥触发都能刷），需要成本侧度量。
- **延迟收益**：价值之后才兑现的介入，目前没有 credit assignment 的故事。

## 横切对比

| 工作 | 信号 | 决策 | 场景 | eval 闭环 |
|---|---|---|---|---|
| Horvitz 1999–2003 | 桌面活动 | 期望效用（收益 − 成本） | 通知，封闭 | 用户研究 |
| Pielot 2017 | 手机传感器 + 行为历史 | 学习的时机分类器 | 移动端触达 | 337 人实地实验 |
| Proactive Agent 2024 | 事件流 | 学习的 reward model（接受/拒绝） | 桌面任务 | ProactiveBench |
| YETI 2025 | SSIM + 脚本对齐 | 规则：偏离即介入，无成本项 | 有脚本的程序性 AR | HoloAssist |
| VisionClaw 2026 | 常开第一人称 | agent 自主决策 | 开放世界眼镜 | 无 |
| SIAgent 2026 | 眼手 | 意图识别（是「听懂」，不是「何时出手」） | VR 任务 | 60+ 任务套件 |
| UI-TARS-2 2025 | GUI 状态 | 任务完成 reward（有 ground truth） | GUI/OS，封闭 | OSWorld 等 |

按列读这张表：信号越来越丰富，执行者越来越强，但**决策列仍然分裂成「没有成本项的规则」和「没有现代执行者的成本模型」两半**，而 eval 列在开放世界场景下还没有一个共享的时机质量 benchmark。

## 开放问题（survey 的种子）

1. **没有 ground truth 的 reward。** GUI agent 有任务完成作 reward；介入质量没有等价物。什么样的 eval 能让 RL reward 变得可定义？
2. **成本项。** 现代主动式工作检测「需要」，几乎没人建模打扰成本。1999–2017 的效用框架怎么移植到 LLM 执行者上？
3. **无脚本的时机。** YETI 式偏离检测需要任务脚本，开放世界的日常场景没有脚本。
4. **延迟收益的 credit assignment。** 帮用户省下明天十分钟的介入，今天拿不到信号。
5. **个人化阈值。** 同一个 θ 对不同用户、上下文、时段都是错的，时机策略必须以记忆为条件。
6. **Benchmark 碎片化。** HoloAssist 的介入类型预测、ProactiveBench 的接受/拒绝、ProactiveEval 的对话框架各测一个切面，没有一个端到端覆盖开放世界 MR 的介入时机。
